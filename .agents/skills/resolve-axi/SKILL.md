# Resolve AXI

Ren owns editorial intent. Resolve AXI resolves live state, selects an eligible execution path, applies the typed operation and reports what read-back proves. Use AXI's current discovery output rather than relying on remembered operation or backend coverage.

## Operating loop

1. **Inspect.** Confirm the exact project, timeline and target through AXI. Stale, missing or ambiguous targets refuse mutation.
2. **Discover.** Start with `bin/resolve-axi --help` and the relevant command's `--help`. Ask the live registry with `bin/resolve-axi capabilities --search "<requested effect>"`, then inspect a candidate with `bin/resolve-axi capabilities <operation> --json`. For Resolve API surface discovery, use `bin/resolve-axi api search "<method or concept>"`, then `api stubs <Type>` or `api docs --section "<heading>"`; `bin/resolve-axi capabilities native_mcp.<tool>` reports the official MCP inventory entry. Discovery identifies evidence and constraints, not permission to bypass semantic edit authorization.
3. **Prepare and execute.** Express the requested change as an AXI semantic `EditRequest`; `bin/resolve-axi edit-request plan <request.json>` prepares and routes it without a Resolve write. Review its exact targets, planned changes, route and refusal reasons. Submit only when authorized: `bin/resolve-axi edit-request submit <request.json> --apply`; check asynchronous work with `bin/resolve-axi edit-request status <job-id> --wait 30`. AXI resolves the eligible execution path and owns authorization, transaction and the single-instance broker/lease. Never select or force a backend for a supported edit. If the request is ambiguous, stale, unsupported, unsafe, or has no eligible route, preserve state and relay the refusal; do not silently substitute another edit or rebuild.
4. **Verify and preserve.** Treat the merged execution receipt as the account of what happened. Check its request/transaction identity, selected route, requested and actual changes, verification evidence, recovery status and lifecycle stage. Then read the exact target back fresh and compare it with the user's requested effect, including item identity and exact timing or properties. Add visual or audio evidence when structural read-back cannot prove the result. Follow [recovery guidance](references/recovery.md) before retrying. `APPLIED` is not `VERIFIED`; `VERIFIED` is not `COMMITTED`; a staged timeline is not promoted; a committed or promoted change is not `DELIVERED` until the requested export and its checks exist. Report only the highest stage the receipt and independent evidence establish.

## Ownership

Use this skill for Resolve mechanics. Use `ren-co-editor` for the user's editorial intent, footage research, approval questions and delivery conversation. Use `reel_build` for the approved reel build workflow, and `verify_timeline` / `verify_render` for their specific gates. Resolve's native API, official MCPs and UI are discoverable execution mechanisms behind AXI, not alternate production write paths. Research Resolve changes with `bin/resolve-axi api whats-new --since <version>` and confirm methods with API search, stubs or docs. Monitor upstream third-party releases for useful capabilities, then check whether AXI already exposes an equivalent. Do not duplicate a native method or expose raw MCP scripting as edit authorization. New operations enter the existing AXI registry and execution path only after implementation and qualification. UI automation remains behind AXI and is not a bypass.

## Generated references

The capability references in `references/` are generated byte-for-byte by `bin/vep -m library.tools.operations --emit-resolve-axi-references` and checked for drift by `tests/tooling/test_skill_source.py`. Do not hand-edit their tables; change the owning registry and regenerate them. Treat the live capability query and the request's receipt as authoritative for the current route and outcome. Open only what the request needs:

- [capability matrix](references/capability-matrix.md) - operation availability, route constraints, recovery and measured cost.
- [concepts](references/concepts.md) - operation vocabulary and evidence meanings.
- [transactions](references/transactions.md) - compilable operations.
- [verification](references/verification.md) - operation read-back contracts.
- [recovery](references/recovery.md) - inverse metadata and limits.
- [backend limitations](references/backend-limitations.md) - execution-route evidence and cross-cutting constraints.

If discovery shows no eligible capability, state that AXI cannot currently perform the requested operation. Do not infer support from a raw Resolve method, a generated row, or a successful API call.
