# Resolve AXI

Ren owns editorial intent. Resolve AXI resolves live state, selects an eligible execution path, applies the typed operation and reports what read-back proves. Use AXI's current discovery output rather than relying on remembered operation or backend coverage.

## Operating loop

1. **Inspect.** Confirm the exact project, timeline and target through AXI. Stale, missing or ambiguous targets refuse mutation.
2. **Discover.** Use `bin/resolve-axi --help`, the relevant command's `--help`, and `bin/resolve-axi capabilities <operation>`. Consult the generated references below when you need full evidence or limitations. Implemented does not mean qualified or production-enabled.
3. **Prepare and execute.** Preserve the requested semantics and unrelated state. Use a guarded or dry-run mode when available. AXI owns target resolution, authorization, backend choice, transaction and the single-instance broker/lease. If no eligible path expresses the request, report the specific refusal; do not silently substitute a rebuild or different edit.
4. **Verify and preserve.** Check the receipt and fresh state against the requested target and effect, including identity and exact timing or properties. Add visual or audio evidence where read-back cannot prove the result. Inspect state before retry or recovery, follow [recovery guidance](references/recovery.md), and report applied, verified, committed and delivered as separate facts.

## Ownership

Use this skill for Resolve mechanics. Use `ren-co-editor` for the user's editorial intent, footage research, approval questions and delivery conversation. Use `reel_build` for the approved reel build workflow, and `verify_timeline` / `verify_render` for their specific gates. Resolve's native API, MCPs and UI are execution backends behind AXI, not alternate production write paths. UI automation from `library/tools/computer_use/` is available only through an AXI-registered and qualified operation; do not use it to bypass AXI.

## Generated references

The capability references in `references/` are generated byte-for-byte by `bin/vep -m library.tools.operations --emit-resolve-axi-references` and checked for drift by `tests/tooling/test_skill_source.py`. Do not hand-edit their tables; change the owning registry and regenerate them. Open only what the request needs:

- [capability matrix](references/capability-matrix.md) - operation and backend status, qualification, recovery and measured cost.
- [concepts](references/concepts.md) - operation vocabulary and evidence meanings.
- [transactions](references/transactions.md) - compilable operations.
- [verification](references/verification.md) - operation read-back contracts.
- [recovery](references/recovery.md) - inverse metadata and limits.
- [backend limitations](references/backend-limitations.md) - backend-specific evidence and cross-cutting constraints.

If discovery shows no eligible capability, state that AXI cannot currently perform the requested operation. Do not infer support from a raw Resolve method, a generated row, or a successful API call.
