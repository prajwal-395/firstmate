# Resolve AXI

Ren decides the editorial result. Resolve AXI resolves live state, selects an available execution path, applies the typed operation and reports what read-back proves. Load this skill for Resolve work; use its discovery surface at the time of the request instead of recalling a fixed command or backend list.

## Operating loop

1. **Inspect current state.** Confirm the exact project and timeline, then read the target items and relevant properties through AXI. Treat stale, missing or ambiguous targets as a refusal to mutate.
2. **Discover the operation.** Start with `bin/resolve-axi --help` and the relevant command's `--help`. Read the generated [capability matrix](references/capability-matrix.md), [capability concepts](references/concepts.md), [transaction map](references/transactions.md), [verification contracts](references/verification.md), [recovery metadata](references/recovery.md), and [backend limitations](references/backend-limitations.md) as needed. The tables are generated from `edit_algebra.OP_STATUS`; a listed implementation is not automatically qualified or enabled.
3. **Prepare the smallest operation that preserves the requested result.** Use a dry-run or explicit non-applying mode where available. Keep the requested semantics, target and unrelated timeline state fixed. If no qualified path expresses the operation, explain the refusal; do not substitute a rebuild or different media treatment.
4. **Execute through AXI.** Production Resolve mutations belong under AXI's transaction and the single-instance broker/lease. Do not call Resolve writers directly or overlap a UI write with a native write.
5. **Verify the requested effect.** Check the returned receipt and fresh state against the request, including target identity, timeline, timing and properties that matter. Use visual or audio evidence when structural read-back cannot prove the requested result. A successful command or rebuild without this check is not a verified edit.
6. **Commit, promote or deliver only what verification supports.** Keep approved edits intact. If execution, verification or promotion fails, inspect actual state before retrying and follow [recovery guidance](references/recovery.md); report applied, verified, committed and delivered as separate facts.

## Ownership

Use this skill for Resolve mechanics. Use `ren-co-editor` for the user's editorial intent, footage research, approval questions and delivery conversation. Use `reel_build` for the approved reel build workflow, and `verify_timeline` / `verify_render` for their specific gates. Resolve's native API, MCPs and UI are execution backends behind AXI, not alternate production write paths. UI automation from `library/tools/computer_use/` is available only through an AXI-registered and qualified operation; do not use it to bypass AXI.

## Generated references

The five capability references in `references/` are generated byte-for-byte by `bin/vep -m library.tools.operations --emit-resolve-axi-references`. Do not hand-edit their tables; change the owning registry and regenerate them.
