# Analysis subsystem

# BUILD THIS ENVIRONMENT ON PYTHON 3.12. It is not a preference: on 3.14
# there is no set of these packages in which transcription works, and the
# failure is silent. Measured 2026-08-17, on project 001's real footage.
#
# The chain, so nobody re-derives it:
#   - 3.14 has no wheel for the ctranslate2 whisperx 3.2.0 pins, so an env
#     built there installs faster-whisper 1.2.1 instead of the 1.0.0
#     whisperx 3.2.0 requires. 1.2.x added `multilingual` and `hotwords`
#     to TranscriptionOptions, so every transcribe call raised
#       TypeError: TranscriptionOptions.__init__() missing 2 required
#       positional arguments: 'multilingual' and 'hotwords'
#   - step_1_04 catches that per clip and carries on. All 17 clips of 001
#     reported "0 regions, 0.0s speech, 0 words" and the run continued.
#     No transcript means no speech selection, no spine and no subtitles,
#     which is the entire edit - reported as success.
#   - Going forward on 3.14 does not help either: newer whisperx needs
#     torchaudio >= 2.9 via torch, and pyannote.audio still calls
#     `torchaudio.list_audio_backends()` and imports `AudioMetaData`, both
#     removed by then. Shimming one surfaces the next.
#
# On 3.12 the resolver finds a coherent set on its own, with a MATCHED
# torch/torchaudio pair, which is the thing that was never true on 3.14:
#   whisperx 3.8.6, faster-whisper 1.2.1, ctranslate2 4.8.1,
#   torch 2.8.0, torchaudio 2.8.0, pyannote.audio 4.0.7
# Verified by transcribing 001 footage, not by importing the module.
whisperx>=3.8,<4
librosa>=0.10
# Step 2.04 searches for music and fetches what it finds. It has shelled
# out to yt-dlp since it was written and this file never carried it, so
# `search_youtube.py` had no caller and no dependency and could never have
# run. The floor is measured, not guessed: on 2026-08-28 the 2026.03.17
# on this machine answered every download with `HTTP Error 403: Forbidden`
# and warned that YouTube extraction without a JS runtime is deprecated,
# while 2026.08.19 downloaded with no runtime and no flags. A stale
# extractor fails in a way that reads like a network fault, so
# `library/tools/music_search.py` reports the version it ran.
yt-dlp>=2026.08.19
